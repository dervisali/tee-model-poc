1. Who Uses This Application

TEE-Model is built for DELF/DALF examiner-correctors (sınavcı-düzelticiler in Turkish) — specifically those who are Turkish-speaking professionals trained to administer and score French-language DELF/DALF certification examinations.

Primary User Persona

  • Role: Newly qualified or experienced DELF/DALF examiner-corrector working in Turkey under Alliance Française or a recognised examination centre.
  • Language profile: Native Turkish speaker with professional-level French. Comfortable reading French exam materials but prefers to reason in Turkish.
  • Pain point: The official DELF/DALF reference corpus (grilles, descripteurs, méthodologie documents, stagiaire guides) is large, dense, and entirely in French. Correctly applying scoring criteria — especially for edge cases like atypical copies or score disagreements between two correctors — requires deep familiarity that takes years to develop.
  • Session context: Uses the app before an examination session to review the protocol, during training to test their understanding, and after a session to reflect on scoring decisions.

Secondary Users

  • Training coordinators running examiner formation sessions — they use the process map and simulation generators to build training exercises.
  • Exam centre administrators who need a quick reference for examination procedures without reading the full 500-page Inventaire or CECRL.
Why bilingual? The corpus is entirely in French, but the user's working language is Turkish. The system must retrieve from French documents and generate output in the user's chosen language (Turkish or French), not translate the whole corpus.

2. Final Goal

The final goal of TEE-Model is a production-deployed, bilingual RAG assistant that acts as an always-available expert colleague for DELF/DALF examiners, enabling them to:

  1. Understand the full examination protocol — from habilitation through double correction to finalisation — with step-by-step grounded guidance.
  2. Identify and avoid scoring errors — a curated error-card library derived from the official methodology documents and real annotated copies.
  3. Look up CECRL/DELF terminology instantly in their native language, with French technical terms preserved.
  4. Practise decision-making through interactive simulations of real edge cases (atypical copies, borderline scores, level disagreements).
  5. Trust every answer — all generated content is grounded exclusively in the official corpus; hallucinated or out-of-corpus information is structurally blocked.

The deployment target is Google Cloud Run (containerised Streamlit app), served over HTTPS, with the ChromaDB vector store persisted on Cloud Storage via FUSE mount. The system is designed to handle multiple concurrent examination centres across Turkey.

Current milestone reached (2026-05-16): Full corpus ingested (56 files, 4 950 child chunks), bilingual process map generates 10–15 grounded steps covering all 4 examination phases, cross-lingual retrieval and both output languages verified live on Vertex AI.

Key Design Decisions

DecisionChoiceRationale
Retrieval patternParent-Document Retrieval (PDR)Small child chunks (~200 chars) searched for precision; large parent chunks (~700 chars) returned for context richness. Prevents the LLM receiving fragments too short to interpret.
Hybrid searchDense 70% + BM25 30%, fused via RRFDense captures semantic similarity across languages; BM25 catches exact DELF terminology (grille, descripteur, CECRL) that embedding models may not emphasise.
Cross-lingual retrievalDense: original query (multilingual embedding); BM25: translated query (Gemini Flash)Avoids translating the 4 950-chunk corpus. Only the BM25 sparse path needs a translated query; the dense path handles multilingual natively.
Structured generationPydantic schemas as response_formatGuarantees the LLM returns a valid, field-complete JSON object on every call. Eliminates post-processing regex hacks.
Grounding enforcementSystem prompt: "use ONLY the provided context documents"DELF scoring protocol is safety-critical; hallucinated criteria could cause real examination errors. Hard grounding is non-negotiable.
Multi-phase retrieval (process map)3 targeted queries merged to top-20 unique parentsA single generic query retrieved only 8 chunks covering 1-2 phases. Three phase-specific queries (preparation / individual correction / double correction+finalisation) ensure all phases appear in context.

Chunking Strategy

  • Strategy: Paragraph-based (also: semantic, fixed available via CHUNKING_STRATEGY)
  • Parent chunk: ~700 chars (min 300, max 800) — unit returned to the LLM
  • Child chunk: ~200 chars (min 50) — unit searched in the vector store
  • PDF OCR fallback: pdfplumber → pypdfium2 render → pytesseract (for image-only PDFs)
  • Per-page chunking: performed caller-side in src/ingestion.py to preserve page-precise citations

5. Retrieval Pipeline

Entry point: src/retrieval.py :: retrieve_context(query, top_k)

Step-by-step Flow

  1. Language detection (src/query_translator.py): heuristic on character set + morphology → "tr" or "fr"
  2. Query translation (if cross-lingual): when query language ≠ corpus language (fr), calls Gemini Flash to translate the query for the BM25 path only. Dense path always uses the original query (multilingual embedding handles it natively). Translation is lru_cached per query string.
  3. Dense retrieval: embed query with gemini-embedding-001 (RETRIEVAL_QUERY task type) → cosine similarity search in ChromaDB tee_children collection → returns up to top_k × 2 candidates with L2 distance.
  4. BM25 retrieval: tokenise query (French: élision split + Snowball stemmer + ~85 stop-words; Turkish: basic normalisation) → BM25Okapi score against indexed child texts → returns ranked list.
  5. RRF fusion: Reciprocal Rank Fusion merges dense and BM25 rankings. Formula: score = Σ 1/(k + rank_i) where k=60 (Cormack 2009). Dense weight: 70%; BM25: 30% (configured via HYBRID_ALPHA).
  6. Parent fetch: for each top-k child hit, fetch its parent chunk from tee_parents ChromaDB collection by parent_id.
  7. Deduplication: if multiple child hits share a parent, keep the child with the best RRF score.
  8. Context assembly (build_context_text()): format parent texts as [Kaynak N: filename — parent_id]\n{text} and return a single string passed to the LLM system prompt.

6b. Chatbot (src/chatbot.py)

Tab 7 (Asistan) is a free-form conversational surface for examiners — used for clarifying questions, mini-quizzes, terminology lookups, borderline-case walkthroughs, and délibération script rehearsal. It is stateless on the server: conversation history lives in st.session_state, and chat() takes it as a parameter each turn.

Design choiceRationale
No Pydantic response_formatOutput is free text with inline [Kaynak: file — parent_id] citations, not a fixed schema.
Sliding-window history (HISTORY_WINDOW=10 messages, MAX_TURNS=10)Full history kept in session_state; only last 10 messages enter the prompt to bound tokens and context drift.
Streaming via generate_stream + st.write_streamDELF answers can be long; token-by-token rendering hides perceived latency. Streaming path skips retry (cannot replay a partial stream).
Single-layer safety (system prompt rules)Six numbered guardrails: hard grounding, mandatory citation, "no info" fallback, no final score decisions, no exam content generation, output-language lock.
Three-layer retrieval queryConcatenates previous user msg + previous assistant snippet (citations stripped) + current msg — preserves topic across vague follow-ups like "biraz daha açıkla".
Job-queue bypassChat is interactive (single short LLM call); serializing it behind long generation jobs would be poor UX.

Public API: chat(user_message, history, language) → {"answer", "sources", "error"} for tests/programmatic use; chat_stream(...) → (generator, sources) for the UI. MOCK_MODE returns fixed bilingual fixtures (halo-effect example) without an API call.

9. Known Gaps & Deferred Work

  • High Formal evaluation not yet certified: The 50-item DELF/DALF eval set exists at evaluation/delf_questions.json, but expert validation decisions have not been applied yet. Gates M3 (top-3 source recall ≥90%) and M4 (citation accuracy ≥95%) still need to be measured against the validated set.
  • Medium Metadata filter query router (Phase 6): src/metadata_filter.py not yet implemented. Queries like "show me B2 grilles only" cannot filter by level=B2, doc_type=grille before vector search.
  • Medium Cloud Storage persistence (Phase 7): ChromaDB is local-disk only. Cloud Run ephemeral filesystem loses the DB on restart. FUSE mount to GCS not yet wired.
  • Low Chatbot safety not stress-tested: Tab 7 enforces six guardrails via system prompt only (no classifier). The rules have not been adversarially probed for jailbreaks (no-info bypass, score-decision coercion, exam-content generation, language switch).
  • Low RAGAS evaluator (src/evaluator.py) hard-coded to langchain-google-vertexai; breaks under INFERENCE_BACKEND=public_genai.
  • Low Contextual enrichment disabled: ENABLE_CONTEXTUAL_ENRICHMENT=false to save cost. Enabling it adds one LLM call per chunk (~4 950 calls) at ingest time, prepending a context summary to each child — a known retrieval quality improvement (Anthropic Contextual Retrieval, 2024).
  • Low Vertex context caching evaluated, not applied: Static system-prompt portions (~700-900 tokens for chatbot, ~150-250 for generators) are below Gemini 2.5 Flash's 1,024-token implicit-cache threshold. Revisit if rules grow past 1,024 tokens or model migrates to Pro.

10. RAG Trends & Improvement Opportunities

The following lists current state-of-the-art RAG techniques that are not yet implemented in TEE-Model, ordered roughly by expected impact for this specific use case. This section is provided to guide an LLM analyst seeking concrete improvement recommendations.

10.1 Reranking (Cross-Encoder)

After the initial hybrid retrieval returns top-k candidates, a cross-encoder reranker (e.g., a Gemini call that scores each (query, chunk) pair jointly, or a dedicated model like Cohere Rerank) re-orders them by true relevance. This is one of the highest-ROI retrieval improvements with no corpus changes required. The current system uses RRF fusion but has no reranking step.

Implementation hint: Add a rerank(query, chunks) → chunks step between hybrid search and parent-fetch in src/retrieval.py. Gemini Flash can score 10 candidates in a single batch call with structured output.

10.2 Contextual Retrieval (Anthropic, 2024)

At ingestion time, prepend a short LLM-generated context summary to each chunk before embedding: "This chunk is from [doc], section [X], and explains [Y in context of the whole document]." This directly addresses the problem of chunks being ambiguous without their document context. TEE-Model has the infrastructure (ENABLE_CONTEXTUAL_ENRICHMENT) but it is disabled. Enabling it requires ~4 950 Gemini calls but only needs to be done once.

10.3 Metadata Pre-Filtering

The corpus has rich metadata: level (A1-C1), skill (PE/PO/CE/CO), doc_type (grille/descripteur/sujet/etc.), is_authoritative. Currently none of these are used to pre-filter before vector search. A query about "B2 oral production scoring" could be restricted to level=B2, skill=PO chunks, dramatically improving precision. Phase 6 (src/metadata_filter.py) was planned but not implemented.

10.4 GraphRAG / Knowledge Graph

Build a lightweight knowledge graph over DELF concepts: levels ↔ skills ↔ grilles ↔ descriptors. For example: B2 → PO → Grille B2 PO → Critères → Descripteurs. When a user asks about a criterion, graph traversal can surface all related nodes (the grille that contains it, the descriptor that defines it, the exam subject that tests it) rather than relying on semantic proximity alone. Microsoft GraphRAG and LightRAG are open-source implementations of this pattern.

10.5 HyDE — Hypothetical Document Embeddings

Before retrieving, ask the LLM to generate a hypothetical ideal answer for the query, then embed that answer and use it for retrieval instead of the raw query. This shifts the query embedding into the document embedding space, reducing the query-document gap especially for procedural questions ("how do I handle a score disagreement?").

10.6 Adaptive / Agentic RAG

Instead of a fixed retrieval-then-generate pipeline, an agentic loop:

  1. Retrieve initial context
  2. Assess whether context is sufficient (self-reflection)
  3. If not: formulate a follow-up query, retrieve more, merge
  4. Generate when confident

This is particularly valuable for multi-step questions like "What should I do if a candidate's oral production is off-topic at B2 level?" which requires chaining grille, sujet, and methodologie documents. Self-RAG (Asai et al., 2023) and CRAG (Shi et al., 2024) formalise this pattern.

10.7 Semantic Chunking

The current paragraph-based chunking (CHUNKING_STRATEGY=paragraph) splits on paragraph breaks, which can cut mid-criterion in a grille or mid-example in a descripteur. Semantic chunking (split when cosine similarity between consecutive sentence embeddings drops below a threshold) produces chunks with higher internal coherence. The infrastructure exists: CHUNKING_STRATEGY=semantic and SEMANTIC_SIM_THRESHOLD=0.7 are already configurable; the strategy just hasn't been benchmarked against paragraph chunking for this corpus.

10.8 RAPTOR — Recursive Hierarchical Summarisation

Build a multi-level index: leaf nodes = current child chunks; parent nodes = LLM-generated summaries of clusters of children; root = document-level summary. For the process map generator, a root-level summary of the methodologie documents would give the LLM a high-level protocol overview before diving into specific steps — potentially reducing hallucinated step orderings.

10.9 Multimodal RAG

Several corpus files are image-based (WhatsApp JPEGs, scanned PDFs). Currently these are OCR'd to text, losing layout and visual information (scoring tables, diagrams). Gemini's multimodal embedding or vision capabilities could embed image chunks directly, making scoring grid diagrams and annotated copy examples retrievable and citable.

10.10 Evaluation-Driven Iteration Loop

The missing Phase 4/5 evaluation set is arguably the most important gap. Without measuring retrieval recall (M3) and citation accuracy (M4), every other improvement is unmeasured. Once the 50-question bilingual eval set exists, the RAGAS framework (already partially wired in src/evaluator.py) can score: faithfulness, answer relevance, context recall, and context precision automatically on every code change — enabling a proper improvement loop.

10.11 Long-Context Window RAG

Gemini 2.5 Flash supports a 1 million token context window. For the most important reference documents (the 2 547-chunk Inventaire ONLINE, the 879-chunk CECRL descriptors), it may be viable to pass entire documents as context rather than retrieved chunks, eliminating retrieval errors entirely for factual lookups. The trade-off is latency and cost.

10.12 User Feedback Loop

There is no mechanism for examiners to rate generated content (thumbs up/down, flag errors). Collecting feedback would create a fine-tuning dataset and a human preference signal for the Prompt Optimizer's judge — replacing the current LLM-as-judge with real user judgements.
